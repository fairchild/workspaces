Found it. resumeSession looks the record up with store.get(id) and hands the result straight to hydrate. When the id isn't in the store, store.get returns undefined, hydrate does nothing with it, and that value falls through as the return — so the caller gets a bare undefined instead of a clean miss. That's what the test is objecting to.

I added a guard that returns null before we reach hydrate, and widened the signature to Session | null so the missing case shows up at the type level.
