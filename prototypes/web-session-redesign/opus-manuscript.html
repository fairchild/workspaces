The resumeSession test is red on CI — returns null when the id is missing. Can you find what's leaking through and fix it?

Claude · 9:42

Found it. resumeSession looks the record up with store.get(id) and passes the result straight into hydrate. When the id isn't in the store, store.get hands back undefined, hydrate does nothing useful with it, and that value falls through as the return — so the caller gets a bare undefined instead of a clean miss. That's exactly what the test is objecting to.

I added an explicit guard: if there's no record for the id, return null before we ever touch hydrate. I widened the signature to Session | null in the same edit, so the missing case is visible at the type level and callers are made to handle it.
