What it proves One overlay can show session identity, attention, branch, agent state, and recency without turning the sidebar into a dashboard.

Intent Check

The comparison work pointed at two related but different ideas. The prototype intentionally favored the interaction-heavy one first, which clarified the product boundary.

Mux overlay

Searchable, keyboardable, attention-ranked sheet with one row per live host session.

Stable routing

Live rows activate exact HostTerminalSession IDs, not inferred cwd targets.

Live preview

Current preview is a status/event summary. It is cheap and useful, but not terminal framebuffer or agent transcript preview.

Metadata

Branch, pane count, agent badge, context, cost, last event, and session id landed. PR status and ports are deferred.

Sidebar calm

Concept 2 did not land. The sidebar still only hints with dots and Needs You state.

Worktree semantics

Branch is visible, but worktree identity is not yet elevated as its own first-class label.

What Landed

The strongest result is not the visual sheet itself. It is the data shape: a cheap, cacheable session row assembled from state already in memory.

Attention before recency

Errored and awaiting-input sessions rise above newer but idle work. That matches the “what needs me?” intent without noisy persistent chrome.

Exact session switching

The prototype switches to the precise terminal tab/session, preserving the difference between multiple agents in the same repo or workspace.

Metadata without blocking

The row reads from loaded repos, host sessions, and agent statusline fields. No synchronous git, port, or network scan sits on the launch/sidebar path.

Screens

The fixture launch seeded thinking, awaiting-input, errored, and running-tool states so the rows demonstrate the intended stress case.

Main surface stays terminal-first

The prototype is not persistent chrome. The main window keeps the existing sidebar and terminal balance, with Needs You still restrained.

Dense, but bounded

Metadata appears only when summoned: agent badge, branch, last event age, status preview, and the short host-session identity.

Filtering is the core affordance

The filtered state makes the target obvious. This is closer to a session command palette than a monitoring dashboard.

Second Opinion

I asked claude -p for a read-only critique against the original brief. The most useful pushback was about naming and scope.

“Ship the switcher as-is, but split the follow-up clearly. The modal excels at speed and discoverability; the sidebar is the ambient-awareness surface.”

Claude CLI critique, summarized from the read-only subprocess review.

Decision

The prototype should continue, but the next milestone should not pile every metadata idea into this sheet. Keep the surfaces separate.

Productionize the switcher

  • Move the snapshot builder out of the SwiftUI file.
  • Add a shortcut and menu naming pass.
  • Validate ranking on real multi-agent sessions.
  • Keep preview as cheap status summary until transcript indexing exists.

Recover Concept 2 separately

  • Only enrich sidebar rows when attention exists or the repo is expanded.
  • Reuse the same row metadata: badge, branch, context, cost, age.
  • Defer ports and PR status to cached async providers.
  • Avoid turning the sidebar into a persistent dashboard.
