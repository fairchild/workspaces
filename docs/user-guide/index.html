Setup

Cloud workspaces run on Daytona sandboxes — remote Linux VMs you can SSH into directly from the app. You need two things to get started:

  1. Get a Daytona API key Sign up at app.daytona.io and generate an API key from your account settings.
  2. Add the key to ~/.env Create or edit ~/.env in your home directory: 
    DAYTONA_API_KEY=your_api_key_here
  3. Install uv The backend currently uses a Python script via uv: 
    brew install uv
Note When WorkSpaces launches, it checks for uv on your system. If found, the "Remote VM" option appears when creating new workspaces. No additional configuration needed.

Creating a Cloud Workspace

  1. Right-click a repository in the sidebar Choose "New Workspace..." from the context menu. The repository must have a remote URL (GitHub, GitLab, etc.) for clone to work.
  2. Pick "Remote VM" in the environment picker Enter a name and switch the environment toggle from Local to Remote VM.
  3. Click Create The sheet dismisses immediately. A spinner appears under the repo with "Creating cloud workspace..." while the sandbox is provisioned and your repository is cloned.
  4. Connect Once created, the workspace appears in the sidebar with a cloud icon. Click it to open an SSH terminal session.
Timing Sandbox creation typically takes 10–30 seconds depending on repository size. The spinner stays visible throughout.

Connecting to a Workspace

Click any cloud workspace in the sidebar to connect. The behavior depends on the workspace state:

State What Happens
Active SSH session opens immediately (or reuses existing session)
Stopped Sandbox starts automatically, then SSH connects. A "Connecting..." overlay shows progress.
Archived Sandbox restores from cold storage, then SSH connects. This takes longer.

You don't need to manually start a stopped workspace — clicking it handles everything.

Disconnecting

Press Ctrl+D or type exit in the terminal to end the SSH session. The sidebar selection automatically updates to reflect which terminal is now active. The remote sandbox keeps running until you stop it.

Lifecycle Management

Right-click a cloud workspace to manage its state. Available actions depend on the current state:

Current State Actions
Active Stop, Archive, Delete
Stopped Start, Archive, Delete
Archived Start, Delete

Stop

Pauses the VM. Disk is preserved, compute billing stops. Fast to resume (seconds). Use this when you're done for the day but want to pick up where you left off.

Archive

Moves the sandbox to cold storage. Minimal cost. Slower to resume since disk needs to be restored. Use this for workspaces you won't touch for a while.

Delete

Permanently destroys the sandbox and removes the workspace from the sidebar. This cannot be undone.

Status sync On launch, WorkSpaces checks the actual state of all cloud sandboxes via the Daytona API and updates the sidebar to match. If a sandbox was auto-stopped or archived externally, you'll see the correct state.

Troubleshooting

"Remote VM" option doesn't appear

WorkSpaces checks for uv on launch. Make sure it's installed (brew install uv) and on your PATH. Relaunch the app after installing.

Connection fails or times out

Check your API key in ~/.env. The key should be on its own line: DAYTONA_API_KEY=dyt_.... Also verify your internet connection — the sandbox runs in Daytona's cloud.

Sandbox won't stop (timeout)

Stop operations have a 180-second timeout. If the sandbox is under heavy load, the stop may take longer. Try again, or archive instead (archive stops the sandbox first, then moves to cold storage).

Status shows wrong state after restart

WorkSpaces syncs cloud workspace statuses on every launch. If it looks wrong, relaunch the app. You can also right-click and use the lifecycle actions to force a state change.

SSH session dies immediately

The SSH access token expires after 8 hours. If your session drops, click the workspace again to get a fresh token and reconnect.
